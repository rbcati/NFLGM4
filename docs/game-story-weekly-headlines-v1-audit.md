# Game Story & Weekly Headlines V1 audit

## Scope and source-of-truth findings

The Weekly GM Briefing is the existing `PostGameSummary` overlay. It already owns the result hero, canonical score card, game leaders, injuries, preparation routes, Game Book route, and Continue action. It is therefore the correct integration surface; this work does not add a modal or navigation step.

`buildGameBookPresentation()` in `src/ui/utils/boxScoreViewModel.js` is the authoritative detailed-game adapter. It merges an archive with its schedule result, reads the strict final score, resolves teams and players, and exposes winner/tie, team totals, player tables/leader cards, decisive moments, injury rows, availability, and legacy quality. Weekly game explanation should consume this model rather than remap the archive.

`buildGameBookStory()` contains older narrative logic over the Game Book model. It emits an unbounded sequence, describes every stat differential, and treats a tie as a home winner before its fallback. `buildPostgameEmotionalFrame()` and `buildPostgameBriefing()` add generic result/momentum copy. `buildWeeklyLeagueRecap()` independently reconstructs records and league ordering from the schedule and labels an “upset” from prior record differential. These are useful audit evidence but are not safe foundations for the requested briefing: the new model limits and ranks factual evidence, requires an explicit pregame probability for “upset,” and does not claim standings movement from reconstructed post-week order.

Completed weekly results arrive in `App.jsx` as `lastResults`; this `WEEK_COMPLETE` payload is deliberately reduced to identity and score fields. The worker has already flushed the full canonical archive before posting `WEEK_COMPLETE`. The briefing therefore waits for `actions.getBoxScore(gameId)` and unwraps the same archive response consumed by Game Book before constructing its story. The local score archive remains only an honest fallback when the canonical archive is unavailable. Schedule resolution supports scalar IDs and embedded team objects. The next opponent is resolved from the saved schedule; canonical `div` is primary with legacy `division` as a fallback, and prior meetings are sorted on copied rows so the most recent is selected without mutating the schedule.

Standings presentation is available through `src/views/standingsView.js`, including authoritative current seeds and division-clinch flags. The advance response does not currently provide a before-week snapshot to the briefing. Consequently, V1 accepts optional explicit before/after rows and only describes movement when both are supplied; it does not add another standings calculator or infer movement from the current table.

Injuries are recorded on roster players (`injuryWeeksRemaining` and legacy nested aliases). The current skip-mode briefing collects the user roster's active injuries, but there is no reliable “new this week” injury ledger in the advance payload. V1 may describe an identified recorded absence and duration, but does not claim when it occurred or diagnose beyond a recorded label.

Rookie identity exists in some player/save paths (`yearsPro`, draft/year fields), and Schedule Center has its own weekly-honors derivation. The canonical Game Book leader cards do not retain an explicit rookie flag. V1 therefore omits rookie-breakout headlines rather than infer from age or independently remap box scores. Awards and league leaders are season aggregates, not authoritative weekly events, and are not used.

Owner-pressure helpers derive presentation state, but the weekly advance payload does not carry an authoritative before/after pressure transition. Hot-seat headlines are omitted. Existing playoff code exposes current seeds and bracket state, but no authoritative weekly transition event for clinch/elimination is supplied to this surface; those claims are omitted. Comeback size, late score differential, and rematch outcomes are only used when directly recorded; no play sequence is reconstructed.

## Final model placement and reuse

`buildWeeklyStoryPresentation()` lives in `src/ui/utils/weeklyStoryPresentation.js` beside the existing Game Book and weekly presentation adapters. It is pure and presentation-only. The small async archive bridge is separate from the model: it requests and unwraps the canonical Game Book archive, after which the pure model calls `buildGameBookPresentation()` once for the user game. The model consumes completed result scores directly, accepts optional standings snapshots, filters recorded injuries, and receives already-resolved next-week context. Components memoize one model instead of sorting or parsing story inputs repeatedly during render.

Implemented categories are: compact user-game evidence (turnovers, meaningful rushing/total-yard/passing/sack advantages, recorded quarter separation, decisive moment, or score-only fallback), closest finish, largest margin, explicitly supported upset, recorded injury, proven division-lead/playoff-seed movement, and factual divisional/rematch/streak/general next-opponent hooks. Candidates use explicit significance values, then stable game/team/player-derived keys. Duplicate category and primary-team subjects are suppressed, and output is bounded to five.

Omitted categories are: comeback without a recorded comeback field; rookie breakout without explicit rookie identity on canonical weekly performers; hot-seat change without snapshots; clinch/elimination without a confirmed transition helper; special-teams causal claims without a meaningful common metric; and unit ranking without a canonical saved ranking. Player-of-the-week headlines remain omitted in this first patch because weekly results do not consistently expose canonical named stat rows in one shape; inventing a second box-score mapping would violate the Game Book ownership boundary.

## Persistence decision and compatibility

Stories are recomputed from saved authoritative facts. No story text, random seed, event, or schema field is persisted. This keeps output deterministic, avoids stale prose, and leaves old saves unchanged. Optional inputs default to absence, score-only games receive one honest fallback, missing standings snapshots prevent movement claims, missing opponent data omits the hook, and bye/rollover weeks render no empty story container. No simulation, ratings, football balance, worker protocol, or IndexedDB schema changes are made.
